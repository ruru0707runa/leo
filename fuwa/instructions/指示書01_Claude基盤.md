# 指示書01 Claude基盤の構築

目的: Claude系の道具を「安全に・課金事故なく・定型作業を任せられる」状態まで導入する。対象は Claude（チャット）、Claude Code、Cowork、Skills、プロジェクト、MCP、拡張機能、スケジュール、Dispatch。
注: 具体的な画面・プラン・料金は変わりやすいため、実行時は現行の公式情報を確認すること。本書は手順の型と判断基準を定める。

## STEP1 使い分けを決める
- 対話と文章作成・相談 → Claude（チャット）
- ファイル作成・編集・実行まで伴う作業、サイトやアプリの作成 → Claude Code
- デスクトップ上のファイル操作や資料作成の代行 → Cowork
- 繰り返す手順の固定 → Skills
- 資料と背景情報の共有 → プロジェクト
- 外部ツールとの接続 → MCP
迷ったら「実行まで必要か」で分ける。文章だけで済むならチャット、成果物ファイルが必要なら Code/Cowork。

## STEP2 導入の型
1. 対応プランと動作環境を確認する（CoworkやCodeは有料プランとデスクトップ環境が前提になることが多い）。
2. 専用の作業フォルダを作り、AIが触ってよい範囲を物理的に区切る。
3. 初回は小さな試運転をする（簡単な資料やページを1つ作らせる）。
4. 権限は最小から始める。削除・送信・公開など影響の大きい操作は承認制にする。

## STEP3 課金事故の防止（必須チェック）
- サブスクリプション利用とAPI従量課金は別物だと理解し、今どちらで動いているかを確認する。
- 使っていないAPIキーが残っていないか確認する。
- 追加利用や自動チャージの設定は初期状態でオフにし、使用量の確認方法と支出上限の設定を済ませる。

## STEP4 CLAUDE.md（プロジェクトの記憶）
各プロジェクトのフォルダに、AIへの恒常指示を置く。含める項目:
- プロジェクトの目的と成果物の定義
- 文体・トーンの指定
- フォルダ構成とファイルの置き場所
- 禁止事項（触ってはいけないファイル、使ってはいけない表現 等）
- 承認が必要な操作の一覧
自動生成された下書きをそのまま使わず、自分の言葉で直してから使う。

## STEP5 Skillsとプロジェクトの設計
- Skillの構成要素: 名前／目的／実行条件／手順／入力の型／出力の型／禁止事項。
- 作成手順: 対象作業の洗い出し → 手順の文章化 → 試運転 → 誤動作の修正 → 定型化。
- 命名規則を統一し、不要なSkillは整理する。共有するSkillに個人情報や認証情報を含めない。
- プロジェクトには背景資料と恒常指示を入れ、Skill（手順）と役割分担する。両者を組み合わせて同じ品質の成果物を量産するのが基本形。

## STEP6 MCP接続
- 接続は「必要な機能だけ」を有効化し、権限を最小限にする。
- 公式または実績のあるサーバーだけを使う。信頼できないサーバーの追加は禁止。
- 接続できないときは、設定ファイルの書式・パス・認証情報・サーバーの起動状態の順に切り分ける。
- 接続先の例: ファイル、クラウドストレージ、カレンダー、メール、タスク管理、ブラウザ操作。

## STEP7 定期実行とリモート操作
- スケジュール機能: Cowork等のタスクを日時指定で自動実行する。向くのは毎日の情報収集、投稿の下書き作成、週次レポート等の定型作業。実行結果の確認先（通知・保存場所）を必ず決める。
- Dispatch: スマホからデスクトップのAIを遠隔操作する仕組み。外出先での進捗確認や軽い指示に向く。遅延と、複雑なタスクの失敗があり得る前提で使う。
- Chrome拡張: ブラウザで見ている情報をAIに渡す入口として使う。権限の確認を怠らない。

## 安全ルール（全STEP共通）
- 金銭の移動、パスワードや認証情報の入力は、AIに直接扱わせない。
- 大きな作業の前に対象ファイルのコピーを取る。
- 外部公開の前には、成果物に秘密情報や個人情報が含まれていないか人が確認する。
