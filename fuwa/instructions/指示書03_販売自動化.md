# 指示書03 販売自動化（Zapier／Make／LINE）

目的: 集客から納品・リピートまでの販売の定型処理を、自動化フローで回す。人による判断（商品設計、価格、個別対応の方針）は自動化しない。

## 全体設計（4段階）
販売フローは次の4段階で設計する。各段階で「トリガー（きっかけ）→ AI処理 → 成果物 → 承認 → 記録」を決める。
1. 集客: 投稿の生成・配信、話題の収集
2. 教育: LINE登録後の歓迎・ステップ配信、メルマガ配信
3. 販売: 決済の検知、案内文の生成
4. 納品とリピート: 納品物の自動送付、購入後フォロー、週次レポート

## 道具の使い分け
- Zapier型（単純な直線連携）: 「Aが起きたらBする」レベルの処理。初心者向けで構築が速い。
- Make型（分岐・繰り返し）: 条件分岐、複数パターン、データ加工が必要な処理。
- AIの接続: 連携プラットフォームの公式AI連携を使う方法と、HTTPリクエストでAIのAPIを呼ぶ方法がある。どちらでも「入力の型」と「出力の型」を先に固定する。
- 料金は両道具とも無料枠＋有料プランの目安を確認し、AI利用料が別途かかる前提で見積もる。

## 標準フローパターン（Miroボードの7型を言語化）
共通骨格: AI生成 → 人の承認 → 配信 → 記録更新。
1. 定期収集型: 素材置き場を定期チェックし、承認済みの素材から予約投稿を作って配信し、記録の状態を更新する。
2. 毎朝生成型: 定刻にAIが投稿文を生成 → 記録へ保存 → 承認 → SNSへ配信。
3. 公開連動型: ブログ等の公開をきっかけに、要約と告知文をAIが作り、SNSへ案内する。
4. 承認配信型: AIが投稿文を作り、担当者の承認を挟んでから予約投稿で配信する（パターン2の承認を厚くした形）。
5. LINE歓迎型（単純）: LINE新規登録 → 記録へ保存 → AIが歓迎文を生成 → 自動返信。
6. LINE分岐型（高機能）: LINE新規登録 → 条件で分岐 → AIが文面を生成して返信 → 記録。反応の良い相手には別の案内を送る分岐を持つ。
7. 話題収集型: SNSやニュースの話題を定期収集 → AIが要約と投稿文を作成 → 配信 → 記録へ保存。

## LINE自動販売の設計
- 流れ: 登録 → 配信（教育） → 決済 → 納品、を一続きにする。
- 役割分担の例: 台本・販売ページなどの「文章資産」は文章生成が得意なAIで作り、処理と管理の実行はエージェント型AIやフロー道具に任せる。
- 公式LINE側の設定（あいさつ、応答の仕組み、外部連携の接続情報）は現行仕様を確認して行う。
- 自動返信で完結させない: 個別相談やクレームの入口は人が受ける導線を必ず残す。

## メルマガ・ステップ配信
- 登録をトリガーに、歓迎文 → 教育コンテンツの連載 → 商品案内、の順で設計する。
- AIに書かせる場合も、最終文面は人が承認する。配信の停止・解除の導線を必ず入れる。

## 決済・納品の自動化
- 決済完了をトリガーに、納品文をAIで生成（または定型文）し、メール等で送る。
- 納品物の置き場とアクセス方法を固定し、購入者ごとに手作業で送らない設計にする。
- 返金・キャンセル・決済失敗の分岐を先に決める。これらは自動処理にせず人の確認に回す。

## 導入計画（4週間の型）
- 1週目: 基盤（道具の契約、接続、記録先の整備）
- 2週目: AI生成の組み込み（投稿・歓迎文・納品文）
- 3週目: 量産と配信の開始（承認フローを回しながら）
- 4週目: 数字を見て改善（反応の良いフローの拡張、止める判断）

## 成果物
フロー設計書（段階ごとに: トリガー／使う道具／AI処理の内容／成果物／承認の有無／記録先／例外時の人の対応）。
